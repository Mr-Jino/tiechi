# tiechi · 不锈钢定制品报价引擎

把"一个门套该报多少钱"从老师傅的脑子里，变成几十行可以直接审查的公式。

门套、窗套、装饰线条这类不锈钢板金活，全国绝大多数工厂到今天还在用 Excel 手工算：展开面积靠估算、损耗拍脑袋、焊多少米靠经验、运费看心情，最后老板在计算器上按一个"加成 30%"就发出去了。这套算法开源在这里，一个字段一个公式，错了你能指出来。

## 它到底算了什么

一件活的成本拆成七项，每一项都有可核对的算式：

| 成本项 | 口径 |
|---|---|
| 材料费 | 净展开面积 ×（1 + 造型损耗）× 板材单价（材质 × 板厚实价表） |
| 折弯费 | 折弯米数 × 元/米，或按道数 × 元/道；弧形另计滚弯 |
| 焊接费 | 焊缝米数 × 元/米 + 拼板接料处数 × 元/处 |
| 表面处理费 | 净面积 × 工艺单价 × 计价面数 × 弧形难度系数 |
| 包装费 | 单套基础费 + 展开面积 × 护边单价 |
| 物流费 | max(体积 × 元/m³, 重量 × 元/kg, 最低一票) —— 泡货重货取大 |
| 安装费 | 品类单价 × 套数，异地加差旅 |

再加三样手工报价永远算不出来的东西：

- **展开几何**：按工艺（拼焊 / 整包）、包法（单包 / 双包）、造型（直边 / 上圆角 / 半圆拱）算出件清单——每条料多长、摊平多宽、折几道、要不要滚弯。这份清单同时是车间下料单。
- **工艺告警**：201 配镀钛会掉色、圆角半径低于 20×板厚会开裂、0.6mm 配宽套线出波浪纹、摊平宽超板幅要拼板、板材利用率低于 55% 建议套裁。这些是老师傅的直觉，写成规则就跑不掉。
- **报价置信度**：价表是出厂默认值 → 低；你改过价 → 中；用实单回填校准过 → 高。避免把"示例价"当成"我的价"发给客户。

## 装

只用标准库，Python ≥ 3.9。

```bash
pip install -e .        # 或者把仓库克隆下来直接跑
tiechi quote --preset 电梯门套 --detail
tiechi cases            # 跑 6 个样例单，验证引擎正常
```

不想装包也能跑：`python -m tiechi.cli quote --w 1000 --h 2100`。

## 价表：行业参数都在这里

引擎不写死任何单价。启动时读 `pricebook.json`（不存在就用代码里的出厂默认值生成一份，路径依次是环境变量 `TIECHI_PRICEBOOK` → 当前目录 → `~/.tiechi/`）。

```bash
tiechi book show                        # 看当前价表与路径
tiechi book set 焊接.焊缝元每米=55       # 改一个价，置信度立刻变"中"
tiechi book set 板材单价.304.1.0=168
tiechi book reset                       # 恢复出厂
```

价表里的分组就是成本结构：`板材单价`（材质 × 板厚实价表）、`表面处理单价`、`折弯`、`焊接`、`损耗率`、`包装`、`物流`、`板幅`、`安装`、`商务`。

> **出厂值是示例值，不是行情。** 它们是 2026 年东北市场的量级参考，带 ★ 的是推导值。用它算出来的报价只能看个大概——真正的价值是结构，数字必须用你自己工厂的采购价和加工费回填。

## Python 里用

```python
from tiechi import calculate

r = calculate({
    "product": "窗套", "opening_w": 1500, "opening_h": 1600, "wall_d": 280,
    "material": "304", "thickness": 1.2, "surface": "镀钛",
    "wrap": "双包", "shape": "上圆角", "arc_radius": 80,
    "quantity": 5, "has_window_sill": True,
})

r["建议报价合计"]     # 16670.0
r["成本明细"]         # {'材料费': ..., '折弯费': ..., ...}
r["算式"]             # 每一项成本的中文算式，可直接印在报价单背面
r["告警"]             # [] —— 这一单没有工艺问题；换成 201+镀钛 就会提醒改 304
r["几何"]["板材张数"]  # 10（含损耗按 1.22×2.44 整张估，利用率 84%）
```

只想拿表单定义生成自己的界面：

```python
from tiechi.schema import INPUT_SCHEMA   # key/label/type/unit/default/group/help
```

## 加一个品类

壁龛、屏风、栏杆、铝板吊顶的展开逻辑各不相同，所以几何按品类分文件：

1. 在 `tiechi/geometry/` 新建 `niche.py`，实现 `build(inp, pb)`，返回固定的那套键（件清单 / 面积 / 折弯米数 / 焊缝米数 / 拼板处数 / 告警）；
2. 在 `tiechi/geometry/__init__.py` 的 `CATEGORY_MODULES` 里加一行。

成本层一行都不用改——它只认"米数、面积、件清单"。

## 它不做什么

- 不是 ERP：不管库存、排产、开票、客户往来账；
- 不含真实行情价：价表是你自己的，引擎只保证算法一致；
- 不做自动识图/识单：洞口尺寸要人量、人填；
- 不替代老师傅：它把经验固化成可核对的口径，判断仍然是人做的。

## 数字可信吗

31 条断言锁的是"业务上讲得通的规律"，不是快照：

```bash
python -m unittest discover -s tests -v
```

比如：双包一定比单包贵；整包没有拼角焊缝但会有接料缝；满焊无缝的焊缝米数等于全部展开总长；物流费一定是体积/重量/最低票三者取大；加成 30% 的实际利润率是 23.1%（0.3/1.3）——这一条是行业里最常见的报亏原因，写成断言了。

引擎移植自一套在用的生产报价系统，首次开源时做过新旧逐位对照：6 个样例单 × 8 个输出字段，差异 0。

```
tiechi/
  pricebook.py      单价表 + 出厂默认值 + 价表读写
  cost_engine.py    七项成本 + 报价 + 置信度 + 算式明细
  geometry/         展开几何（door_window 门套窗套 / lines 装饰线条）
  schema.py         输入字段定义
  cli.py            命令行
tests/              31 条断言
docs/               成本模型 / 工艺与几何
```

## 口径出处

算法与参数口径来自实际生产报价单和车间反馈，不是从教科书推的。`docs/成本模型.md` 写了每一项为什么这么算，`docs/工艺与几何.md` 写了摊平宽度、焊缝米数、折弯扣减这些容易扯皮的地方。
